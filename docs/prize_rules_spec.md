# 奖级规则规范（唯一真相源）

> 版本：v2.5.0 · 2026-10-22
> 权威实现：`data/pick_advisor.py::judge_prize`
> 镜像表：`data/games.py::PRIZE_RULES`
> 守门脚本：`scripts/check_prize_consistency.py`（已纳入本地 CI）

---

## 0. 为什么需要这份文档

v2.5.0 之前，项目里存在**两份**奖级规则：

| 来源 | 谁在用 | 后果 |
|---|---|---|
| `data/pick_advisor.py::judge_prize` | 实际判奖、历史回测 | 真实结果 |
| `data/games.py::PRIZE_RULES` | 期望值计算、蒙特卡洛模拟、向量化 lookup | **错误的** |

两者长期不一致（**15 处**），导致：

- 期望值算错（用了缺项的表）
- 模拟中奖率算错（查表漏判）
- 回测判奖与期望值对不上（同一注号，两边算的奖级不同）

**本规范确立一条铁律**：

> **期望值 / 模拟 / 报表 一律以 `judge_prize` 为准。**
> `PRIZE_RULES` 是它的**镜像**，只允许跟随，不允许独立演化。

任何一方改动，必须同步另一方，并跑 `scripts/check_prize_consistency.py` 确认 0 处不一致。

## 1. 统一口径：浮动奖取**保底金额**

浮动奖（一、二等奖）实际派奖金额随奖池浮动，官方公布的是**上限**。
本项目**一律取保底金额**，理由：

1. **保守** —— 保底是实际到手金额的下界，低估期望值比高估安全
2. **可复现** —— 上限会随期变化，历史回测不可比
3. **不夸大** —— 本项目的立场是诚实，用上限会虚增期望收益

> 这是一个**明确的取舍**，不是数据缺失。若将来要切换到"按期实际派奖"口径，
> 必须同时重算所有对外数字并标注口径。

## 5. 改动奖级规则的正确流程

1. 改 `data/pick_advisor.py::judge_prize`（权威）
2. **同步**改 `data/games.py::PRIZE_RULES`（镜像），注释里写清理由
3. 跑守门脚本：

   ```bash
   python scripts/check_prize_consistency.py
   # 必须输出 "✅ 完全一致"
   ```

4. 跑本地 CI（已包含守门脚本）：

   ```bash
   python scripts/ci_local.py
   ```

5. 重算所有受影响的对外数字（README / CHANGELOG / 报告图）：
   - 期望净收益、返奖率
   - 任何写死期望值的代码 → **改成从奖级表实时计算**（v2.5.0 已清理
     `main.py` / `analytics/recommender.py` / `scripts/pick_gui.py`）
   - 重新生成门面图：`python scripts/make_headline_chart.py --game dlt`

6. 更新本文件的第 2 / 3 / 4 节，并在 CHANGELOG 记一条
